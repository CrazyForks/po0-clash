# 0004. 每秒只读轮询白名单

- 状态：已采纳（刷新间隔与 token 存储由 [0005](0005-token-list-and-poll-interval.md) 修订）
- 日期：2026-09-28

## 背景

po0 白名单按 /24 记录，上限 5 条，写满后按写入时间 FIFO 淘汰最旧的一条。服务端没有删除接口，
也不能指定替换某条普通记录（DELETE / PUT 返回 405，`add` 不接受指定 IP），唯一能指定位置的写入是 `add?slot=N`。

原实现与 po0fw 一致：每 10 分钟（及网络变化时）直接 `POST …/add`。某台设备换到新网段时会挤掉最旧的一条，
那条可能正被另一台设备使用，而被挤掉的设备要等到自己下一个周期（最长 10 分钟）才补回。

曾考虑让设备优先替换「自己以前用过、且没有别的设备在用的网段」。但普通记录无法被指定替换，只能改成自动占用固定槽位；
而且接口不返回设备标识或时间戳，无法判断某个网段是否仍有别的设备在用。

## 决定

- 每秒对每个 token 发一次只读 `GET …/<token>`；只有当前出口不在白名单（或 `@N` 的出口仍在 FIFO 区）时才走常规 `POST …/add`。
- 只要同时在用的网段不超过白名单容量（5 减去固定槽位数），FIFO 的连锁淘汰最终会停在没有设备在用的旧记录上，
  途中每台被挤掉的设备约 1～2 秒内补回。
- 请求复用 keep-alive 连接；网络变化、超时或出错时丢弃连接。连续失败按 2 / 4 / 8 / 16 / 30 秒退避。
- Android 只在亮屏时轮询：熄屏后停止，亮屏时立即检查。原生 `Po0ScreenPlugin` 把 `ACTION_SCREEN_ON/OFF`
  通过 `$packageName/po0_screen` 通道转给 Dart。不持有 WakeLock。
- 轮询仍由 Dart 侧的 `Po0Firewall` 负责，不在 Android 原生服务中另写一份。

## 后果

- 被其它设备挤出白名单后约 1～2 秒恢复，远快于原来的 10 分钟。
- 每台设备每个 token 每秒一次 GET（约每天 8.6 万次）。服务端是否限流没有公开说明；出错时的退避可以减轻压力。
- 同时在用的网段超过容量时，各设备会每秒互相挤占，谁都无法稳定留在白名单中。
- 只装 po0fw 脚本、软路由或 MacroDroid 的设备仍按它们自己的周期（10～15 分钟）补回。
- Android 从最近任务划掉 FlClash 后，Flutter 引擎随界面销毁，检查停止；重新打开应用即恢复。
- 不再提供定时间隔设置；旧配置中的 `interval` 字段在读取时被忽略。
