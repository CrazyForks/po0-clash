# 0005. token 列表与可调刷新间隔

- 状态：已采纳，固定槽位部分已取代（见 [0007](0007-remove-fixed-slots.md)）
- 日期：2026-09-28
- 修订：[0004](0004-per-second-read-only-polling.md) 中「检查频率固定每秒一次」「不再提供定时间隔设置」

## 背景

po0.5 把检查改成每秒一次只读查询，间隔写死为 1 秒；token 仍沿用 po0fw 的单个字符串（`pgnfw_a,pgnfw_b@0`）。
多台 po0 机器的用户需要分别辨认、增删各自的 token，而字符串里既放不下备注名，逐个修改也容易出错。
每秒一次的请求量（每台设备、每个 token 约每天 8.6 万次）也不是所有人都需要。

## 决定

- `Po0FirewallProps.tokens`（字符串）改为 `tokenEntries`：每项为 `token`、可选 `name`、可选 `slot`。
  页面以列表逐项添加、编辑、删除；token 必须是单个 `pgnfw_` 值，不含空格、分隔符与 `@`，同一 token 不能重复。
- 读取配置时，若只有旧的 `tokens` 字符串，用 `parsePo0Tokens` 转成列表（保留 `@N` 为槽位）；已有 `tokenEntries` 时忽略旧字段。
- 新增 `pollSeconds`（1～3600，默认 1；2026-09-29 起默认改为 5，已保存的值不变）。字段名刻意不复用旧的 `interval`：旧字段单位是分钟，复用会把「10 分钟」读成 10 秒。
- 退避以间隔为基数：间隔的 2 / 4 / 8 / 16 倍，最长 30 秒；间隔本身超过 30 秒时不再额外退避。
- 每个 token 仍各自查询、各自补加；只改备注名不触发额外加白。

## 后果

- 旧配置无需用户操作即可升级；降级回 po0.5 会丢失列表（po0.5 只认 `tokens` 字符串）。
- 把间隔调大可以减少请求量，但被挤出白名单后的恢复时间随之变长（约等于一个间隔）。
