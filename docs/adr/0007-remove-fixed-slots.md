# 0007. 去掉固定槽位

- 状态：已采纳
- 日期：2026-09-29
- 修订：[0004](0004-per-second-read-only-polling.md)、[0005](0005-token-list-and-poll-interval.md) 中与固定槽位（`@N` / `slot`）有关的部分

## 背景

po0 服务端允许 `POST …/add?slot=N` 把当前出口钉在槽位 N，钉住的记录不参与 FIFO 淘汰。po0-clash 让每个 token 可选填一个槽位号，
设备据此把自己的出口写进该槽位。实际使用中出现了三类问题，而客户端都无法可靠解决：

- 同一个 /24 在白名单里只能出现一次。出口已在普通区或别的槽位时，`add?slot=N` 会被拒，而每轮检查都会重发，持续报错。
- 槽位 N 已被别的网段占用时，写入要么顶掉另一台设备的记录（两台都钉同一槽位时每秒互相覆盖），要么被拒而本机出口根本没有加白。
- 接口没有删除和移动操作。关闭固定槽位后，服务端那条记录永久保留，继续占用一个位置，旧网段也一直留在白名单里，只能到 po0 面板手动删除。

接口不返回设备标识或写入时间，无法判断某个槽位属于哪台设备、是否仍在使用。

## 决定

- 去掉固定槽位功能：token 只有 `token` 和可选 `name`，加白只走普通 `POST …/add`，不再发送 `?slot=`。
- 读取配置时忽略旧版本保存的槽位号（`tokenEntries[].slot`），旧的 po0fw 字符串中的 `@N` 后缀同样丢弃。
- 结果类型去掉「槽位冲突」；403 与其他带 JSON 说明的错误一样显示为「请求被拒绝」。
- 服务端已有的固定槽位记录照常显示在白名单里（带图钉），当前出口落在这类记录里时视为已加白。

## 后果

- 每台设备只会占用普通区的位置，不会再出现槽位冲突或设备之间互相覆盖。
- 家宽等需要常驻的网段不能再由 po0-clash 钉住；需要时在 po0 面板或其他工具里设置，po0-clash 不会改动已有的固定记录。
- 以前由 po0-clash 钉上去的记录不会自动消失，仍需在 po0 面板删除。
